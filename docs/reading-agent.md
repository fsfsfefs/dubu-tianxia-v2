# 深度问答

在阅读器的 AI 助读中选择「单书全文」或「多书联系」，再点击「深度问答」并发送问题。
普通问答保持原有单次检索方式；深度问答可根据已找到的证据决定是否追加查询或读取相关页上下文。

## 执行流程与预算

1. 检索用户选定的书籍，保留书名与 PDF 页码。
2. 模型检查证据，最多两轮，每轮最多两条补充查询和两处相关页上下文读取。
3. 依据实际检索到的证据流式回答；只有用户勾选「联网查证」时才进行一次网络查询。
4. 对教材引用执行现有 AI 核验，失败时显示本地匹配结果与提示。网络来源单独展示，不代表已自动证明其真实性。

最多四次模型调用（两次计划、一次回答、一次核验）。每轮计划最多输出 1024 Token，回答最多 4096，核验最多 2048；模型配置较低时遵循较低值。
原文证据最多 24 个片段、24000 字符；单个上下文页读取前 2400 字符，不代表完整阅读该页。
模型计划与核验分别限时 45 秒，网络检索 20 秒，Agent 总时限 240 秒（不包含前端首次索引）。
字符限制不是输入 Token 精确计费；实际开销取决于模型、内容和执行轮次。

## 进度、取消与边界

- 当前步骤与「取消问答」始终显示在回答区上方，过程记录可以展开查看。
- 取消通过 AbortController 关闭流式请求，后端取消当前异步调用并停止后续步骤；服务商已执行部分的费用不保证退回。
- 首次索引的 OCR 工作在当前页处理完成后响应取消，已索引的页面保留。
- 深度问答是单次交互，不是持久化后台任务。页面关闭后不继续生成，也不支持断点恢复。
- 只能检索所选书籍，读取已召回页及相邻页，不允许模型访问任意文件或执行命令。
- 无效计划会退回已有证据回答；无证据时明确说明不足。核验结果仍需结合原文判断。

自动化测试使用模拟模型与隔离数据，不消耗用户 API 额度。
