# 外部学习结构导入

教材总览页支持导入 `.md`、`.txt` 和 `.json` 文件。解析、章节匹配与保存均在本地完成，
不会请求 AI 接口，因此不会消耗 API Token。

## Markdown / TXT

推荐在章节标题后写明 PDF 页码。标题下方直到下一个章节标题之间的正文，会作为该章总结导入。

```markdown
# 全书知识结构

## 第1章 操作系统引论 PDF 11-34

本章说明操作系统的目标、作用和发展过程。

### 1.1 操作系统的目标和作用 PDF 11-17

操作系统需要兼顾方便性、有效性、可扩充性与开放性。

### 1.2 操作系统的发展过程 PDF 18-25

总结批处理、分时、实时和现代操作系统的演进关系。
```

没有填写页码时，系统会尝试按照标题与 PDF 自带书签匹配；无法匹配时，会继承前一个已识别
章节的页码。为保证原文跳转准确，建议外部文件包含 `PDF 起始页-结束页`。

## JSON

```json
{
  "book_summary": "全书主线与知识结构……",
  "chapters": [
    {
      "title": "第1章 操作系统引论",
      "start_page": 11,
      "end_page": 34,
      "depth": 0,
      "summary": "本章总结……",
      "children": [
        {
          "title": "1.1 操作系统的目标和作用",
          "start_page": 11,
          "end_page": 17,
          "summary": "本节总结……"
        }
      ]
    }
  ]
}
```

导入完成后，全书结构会立即显示；识别出的章节会出现在左侧目录中。已提供正文的章节直接
标记为已有总结，之后生成全书结构时会优先复用这些总结，只为缺失部分调用 AI。

## 自动分块总结与恢复

生成章节结构时保留已识别的完整原文，每块最多约 7000 字符，超长单页也会拆分并保留 PDF 页码。
多块先分别总结，再以约 10000 字符一组分层汇总；大章和全书汇总也走同一流程，不截断末尾章节。

模型报告输出额度耗尽时自动二分输入，最多递归三层；过小分块仍失败时提示提高最大输出 Token。
这不能保证任意模型在任意额度下都能完成。失败块的未完成正文不会作为成功结果保存。

每个成功块和中间汇总即时保存到 SQLite，暂停、取消、关闭页面或请求失败后，重新生成会复用已完成结果。
断点键包含原文、提示词、模型配置和页码的 SHA-256；变更这些内容会生成新断点。
最终章节结构单独保存，临时分块不会出现在章节列表；完整 ZIP 备份会包含数据库中的断点。
暂停会在当前块保存后生效，取消会停止当前请求。多层汇总最多四层，达到限制时保留断点并提示重试。
分块会增加模型调用次数及费用，进度区显示当前分块或汇总阶段。

自动总结现已移到后端持久化任务中心；仅原文/OCR准备阶段仍由页面执行。进度、暂停和恢复说明见 [后台任务](background-tasks.md#结构总结任务)。

若章节因服务商内容审核被标记“待补充”，可按原章节标题及 PDF 页码导入人工总结。成功保存对应章节后清除该项待补充标记；随后重新执行全书总结可基于已补齐内容重建上级汇总。

推荐在待补充清单点击“导入本章人工总结”，选择MD/TXT正文。此入口只更新该章总结，不替换目录或全书总结；然后重新执行全书结构更新上级汇总。
