# 后台索引与任务中心

Reader Next 在 FastAPI 进程中维护一个单工作线程的持久化任务队列。PDF 导入后会自动创建
`document-index` 任务；用户离开阅读页后，索引仍会继续。

任务记录保存在 SQLite 的 `background_tasks` 表中，包含排队、运行、取消中、暂停、完成、
失败和已取消状态。服务异常重启时，未完成任务会标记为“已暂停”，可在任务中心重新执行。

后台索引流程：

1. 使用 pypdf 读取 PDF 文字层和总页数。
2. 已有 OCR 或文字层数据的页面直接复用，避免重复处理。
3. 新文本写入 `ocr_pages`，同时更新 FTS5 与当前向量模型索引。
4. 没有文字层的扫描页记录为空白页，不伪造内容；用户打开阅读页后可用现有 OCR 补充。
5. 取消任务时保留已经完成的页面，后续重新执行会从缺失页面继续。

任务中心支持：

- 索引当前教材；
- 批量索引全部教材；
- 查看逐页进度和结果统计；
- 取消运行中的任务；
- 重新执行暂停、失败或取消的任务；
- 清理已结束的任务历史。

相关接口位于 `/api/tasks`，任务和教材数据均只保存在本机。

## 结构总结任务

`structure-summary` 与索引共用单工作线程队列，同一本教材同时只运行一个总结任务。
点击章节或全书生成时，页面先准备指定范围的原文（扫描页仍使用本地 OCR），任务中心显示准备进度。
准备完成后提交 `/api/tasks/summary`，由后端独立执行分块生成和分层汇总，不依赖页面、SSE连接或浏览器计时器。
任务中心显示当前章节、分块、汇总层次及已完成章节数；可暂停、取消、重新执行并查看教材。
恢复时复用 SQLite 中的成功分块和已完成子章节，任务参数只保存模型配置ID与目录，不保存 API Key。

暂停或取消在模型返回增量或当前请求结束后生效（最长受模型请求超时约束），不会立刻终止服务商已经开始的计费。
任务等待结束时可在队列中提交继续执行。服务退出或重启后，未完成任务转为暂停，需要点击“重新执行”。
后端进程和电脑须保持运行；关闭或冻结浏览器不会影响已提交任务，但会影响尚未提交的 PDF/OCR 准备阶段。
失败原因保留在任务记录中。完成后教材总览会通过轮询刷新已保存总结，重新打开页面也能看到任务和结果。

总结分块发生传输中断、超时或 HTTP 502/503/504 时，最多自动重试2次，退避约1秒和2秒。每次重试丢弃当前块的残缺正文，不重复已完成块；401等配置错误不自动重试。重试仍失败时保留任务记录和断点，可手动重新执行。重试可能增加模型调用费用。

Responses 的未完成响应会保留原因码、响应编号与失败阶段。已知临时服务故障可重试；Token 上限触发有界缩块；内容审核或未知原因不盲目重试，需依据控制台详情处理。旧失败记录的原因若此前未保存，无法事后还原。

## 请求突增与速率限制

总结工作线程共享请求节流器，默认调用起点至少间隔3秒，发生限流后至少间隔10秒。
HTTP错误体、普通SSE错误与Responses失败事件中的 RequestBurstTooFast / ServerOverloaded / RPM/TPM限流统一识别。
限流重试改为30秒、60秒，最多两次，若服务商Retry-After更长则遵循该时间；超过120秒的等待要求不自动长时间占用任务。
最终失败后仍保留冷却期，同一后端进程中手动重新执行也不会立即再次请求；等待阶段响应暂停/取消。
任务中心显示等待倒计时，余额不足、配置错误或内容审核不作限流重试。
节流只能降低请求突增，不能解除服务商资源保护；同账号其他客户端或服务端资源紧张仍可能触发限制。

## 内容审核与“部分完成”

只有明确的输入/输出内容审核拦截（例如输入可能含敏感信息的HTTP400、Responses content_filter）会隔离当前章节继续处理其他章节。
普通400参数错误、鉴权、网络、限流等错误不会被误当作“可跳过章节”。审核失败不会自动缩块重写或更换服务商重送被拦截文本。
本章失败时保留已有总结，独立记录 `summary_gaps`；上级汇总仅使用已成功生成的材料，并附加确定性的待补充清单。
无可用证据时只显示缺失说明，不调用模型补写章节。任务以 `partial`（部分完成）结束，进度表示已处理数量，不代表全部章节已成功生成。
目录、总览和任务中心显示待补充范围。任务中心列表为本次执行的历史记录，总览清单为教材当前状态。
人工导入或生成对应章节成功时清除待补充标记；重新执行会重新尝试未完成章节并重建带有不完整标记的上级汇总。
清理历史不删除待补充清单；删除教材时级联删除；SQLite完整备份包含该清单。
